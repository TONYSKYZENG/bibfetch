# bibfetch

从 Markdown 笔记或 HTML 文档（例如 Google Docs / Word 导出的网页目录如 `usr/RVVAE`）中的 `##### 年份. 会议/期刊. 标题` 或 `<h5...>年份. 会议/期刊. 标题</h5>` 小标题批量提取文献，用 **OpenAlex** 检索，优先选择正式会议/期刊版本，自动生成并合并高保真 BibTeX。未找到的条目会在终端、`.missing.txt` 和 `.report.json` 中明确告警。

## 功能

- 支持指定 **Markdown 文件**（`.md`）或 **HTML 网页/导出目录**（`.html`，如 `usr/RVVAE`），提取对应层级的标题，例如：
  ```markdown
  ##### 2026\. ACL Findings. Failure Makes the Agent Stronger: Enhancing Accuracy through Structured Reflection for Reliable Tool Interactions
  ```
  或者 HTML 文档中的：
  ```html
  <h5 class="c11"><span>2026. ACL Findings. Failure Makes the Agent Stronger: Enhancing Accuracy through Structured Reflection for Reliable Tool Interactions</span></h5>
  ```
- 用 OpenAlex 的标题精确检索；精确检索失败时自动退化为关键词检索。
- 对候选结果打分，优先级为：
  1. 标题相似度高；
  2. 正式期刊/会议记录优先于 arXiv、SSRN、机构库等预印本；
  3. 年份接近标题中的年份；
  4. 会议/期刊名称与标题中的 venue 匹配。
- DOI 可用时，通过 DOI content negotiation 获取出版社/Crossref 返回的 BibTeX；失败时再根据 OpenAlex 元数据构造条目。
- 自动生成稳定、可读、无冲突的 citation key，例如 `su2026failure`、`yao2022react`。
- 所有条目按 Markdown 中出现顺序合并到一个 `.bib` 文件。
- 未找到、只找到预印本、标题模糊匹配、年份/venue 不一致、缺少 DOI、BibTeX 获取失败等情况都会产生警告。
- 无第三方依赖，只用 Python 标准库；带磁盘缓存，重复运行不会重复消耗 OpenAlex 配额。

## 安装与运行

要求 Python 3.10+。

### 方式 1：一键自动安装（推荐）

直接在终端运行项目内置的自动安装脚本：

```bash
chmod +x install.sh
./install.sh
```

脚本将自动检查 Python 环境并完成所有依赖（包括 PyQt5）的安装与命令绑定。

### 方式 2：使用 pip 安装

可以直接使用标准命令安装，核心依赖将自动安装：

```bash
pip install -e .
# 或使用 requirements 文件：
pip install -r requirements.txt
```

### 方式 3：免手动安装运行（智能按需安装）

如果未预先安装 PyQt5，直接启动 GUI 时系统会自动检测并在当前环境中静默补齐安装：

```bash
python3 -m gui
```

启动命令行检索：

```bash
python3 -m bibfetch XXX.md -o references.bib
# 安装后也可直接使用命令：
bibfetch XXX.md -o references.bib
bibfetch-gui
```

## 图形界面（PyQt5）

界面功能：

- 导入 Markdown 后，左侧表格显示标题和年份，默认按年份降序排列；
- 只找到 arXiv 记录的条目会在最左侧用 `!` 标出，并在右侧给出提示；用户在右侧编辑区手动覆盖后，`!` 会自动消除；
- 右侧编辑区可以直接粘贴完整 BibTeX 覆盖自动结果，覆盖优先参与编译；“恢复自动”可删除覆盖；
- 支持**手动插入文献**（`Ctrl+Shift+N` 或工具栏按钮）：可手动输入标题、年份、会议/期刊，支持从 Markdown 标题或直接从完整 BibTeX 自动填充元数据；
- 支持**源 Markdown 刷新同步**（`F6` 或工具栏按钮）以及磁盘文件变动**自动同步**：外部编辑并保存 Markdown 文件后，工程将自动同步新增条目，同时完整保留用户的手动插入条目与手动覆盖记录；
- 工具栏直观提供“编译 BibTeX”按钮（快捷键 `Ctrl+B`），自动生成单个 all-in-one `.bib`，条目统一按年份降序排列；
- “抓取缺失”在后台线程查询 OpenAlex，不阻塞界面；支持项目设置中的邮箱、API Key、缓存等参数（API Key 只保存在内存中）；
- 工程保存为 `*.bibgui.json`，包含 Markdown 路径、输出路径、检索参数、自动结果、手动插入、手动覆盖和警告信息，可随时重新打开继续编辑。

快捷键：`Ctrl+B` 编译，`F5` 抓取缺失，`Ctrl+Return` 抓取选中，`Ctrl+I` 导入 Markdown，`F6` 刷新源 MD，`Ctrl+Shift+N` 手动插入文献，`Ctrl+S` 保存工程。

工程 JSON 的最小结构示例：

```json
{
  "version": 1,
  "name": "XXX",
  "markdown": "XXX.md",
  "output": "XXX.bib",
  "options": { "heading_level": 5, "min_similarity": 0.9 },
  "entries": [
    {
      "title": "Some paper",
      "year": 2026,
      "status": "manual",
      "manual_bibtex": "@inproceedings{key2026some, ...}"
    }
  ]
}
```

## 常用参数

```bash
python3 -m bibfetch notes.md \
  --mailto you@example.com \
  --api-key "$OPENALEX_API_KEY" \
  --heading-level 5 \
  --min-similarity 0.90 \
  --strict
```

| 参数 | 说明 |
| --- | --- |
| `markdown` | 要扫描的 Markdown 文件 |
| `-o, --output` | 合并后的 `.bib` 路径，默认与 Markdown 同目录同名 |
| `--heading-level` | 扫描的标题层级，默认 `5`，即 `#####` |
| `--min-similarity` | 标题归一化相似度阈值，默认 `0.90` |
| `--min-score` | 候选综合得分阈值，默认 `5.0` |
| `--mailto` | OpenAlex polite pool 邮箱，也可用环境变量 `OPENALEX_MAILTO` |
| `--api-key` | OpenAlex API key，也可用环境变量 `OPENALEX_API_KEY` |
| `--per-page` | 每次 OpenAlex 查询检查的候选数，默认 `25` |
| `--cache` | 缓存文件路径，默认 `~/.cache/bibfetch/openalex.json` |
| `--cache-ttl` | 缓存有效期（天），默认 `30`；设为 `0` 表示不过期 |
| `--no-cache` | 禁用磁盘缓存 |
| `--report` | JSON 报告路径 |
| `--missing` | 未找到条目报告路径 |
| `--no-report` | 不写 JSON 报告 |
| `--strict` | 有未解析条目时返回退出码 `2` |
| `-q / -v` | 只显示警告 / 显示调试信息 |

## 图形界面（GUI）

除了命令行，项目还提供了一个基于 Tkinter 的桌面界面，用来管理多个 Markdown → BibTeX 工程：

```bash
python3 -m gui
# 或安装后：
bibfetch-gui
```

> GUI 需要 Python 自带 `tkinter`。macOS 上用 Homebrew 安装的 Python 默认可能缺少它，可执行
> `brew install python-tk@3.14`（按你的 Python 版本替换），或使用 python.org 的安装包。

界面工作流：

1. **新建工程 / 打开工程**：工程状态保存在独立的 `*.bibgui.json` 文件中，包括 Markdown 路径、输出路径、检索设置、每条文献的检索结果和手动覆盖。
2. **选择 Markdown → 导入 Markdown**：按 `##### 年份. venue. 标题` 解析标题；重新导入时，标题未变的条目会保留已检索结果和手动覆盖。
3. **检索全部 / 检索选中**：在后台线程中调用 OpenAlex，列表实时显示**命中的文献标题和年份**、来源、DOI、引用键。
4. **arXiv 提醒**：命中记录属于 arXiv 的条目会在标题前和“标记”列显示 `❗`。其他警告显示为 `⚠ n`。
5. **手动覆盖…**：双击条目或点击按钮，把从 Google Scholar、出版社或 arXiv 复制的 BibTeX 整条粘贴进来；Generate 时手动覆盖优先。
6. **Generate**：把所有已找到/手动覆盖的条目合并写入 `.bib`。文件头会记录来源和 `Entries: found/total`。

工程 JSON 不保存 OpenAlex API Key；界面“设置”里的 API Key 只在本次运行有效，未填写时读取环境变量 `OPENALEX_API_KEY` / `OPENALEX_MAILTO`。

## 输出说明

`XXX.bib`：

```bibtex
% Generated by bibfetch
% Source: XXX.md
% Generated: 2026-11-10T15:17:10+08:00
% Entries: 21/21 found

@inproceedings{su2026failure, title={Failure makes the agent stronger: ...}, ...}
```

`.report.json` 记录每个标题的：

- 原始标题与行号；
- 是否找到；
- 选中的 OpenAlex 记录、DOI、来源类型；
- 标题相似度、综合得分；
- BibTeX 来源（DOI 协商或 OpenAlex 元数据）；
- 所有警告。

`.missing.txt` 只在有未找到条目时生成，例如：

```text
# Missing BibTeX entries (1)

- line 101: 2026. arXiv (cs.AI). Some Missing Paper
  reason [not_found]: no OpenAlex record met the title-similarity and confidence thresholds
```

## 警告类型

| code | 含义 |
| --- | --- |
| `not_found` | OpenAlex 没有找到足够可信的匹配，条目缺失 |
| `preprint_only` | 只找到 arXiv/SSRN/机构库记录，没有正式版本 |
| `venue_mismatch` | OpenAlex 来源与标题中的会议/期刊不一致 |
| `year_mismatch` | OpenAlex 年份与标题年份相差超过 1 年 |
| `fuzzy_title_match` | 标题相似度低于 0.97，建议人工核对 |
| `missing_doi` | 记录没有 DOI，BibTeX 由 OpenAlex 元数据构造 |
| `bibtex_fetch_failed` | DOI 存在但 DOI 协商失败，已退回 OpenAlex 元数据 |
| `openalex_request_failed` | OpenAlex 请求最终失败（网络/配额/服务端错误） |
| `duplicate_heading` | 重复标题，仅保留第一次出现 |
| `heading_parse_failed` | 标题不是 `年份. venue. 标题` 格式 |

`--strict` 模式下，只要还有 `not_found` 条目，程序返回 `2`，便于在 CI 或批量脚本中拦截。

## 模块结构

```text
bibfetch/
  md_parser.py     # 解析 ##### 年份. venue. 标题
  models.py        # HeadingEntry / Candidate / Issue / ResolvedEntry
  openalex.py      # OpenAlex 查询、DOI BibTeX 获取、重试与限速
  cache.py         # 原子写入的 JSON 磁盘缓存
  matching.py      # 标题相似度、venue 别名、候选打分与正式版本优先
  bibtex.py        # citation key、Crossref key 重写、OpenAlex 元数据构造 BibTeX
  pipeline.py      # 检索 -> 选择 -> 解析 -> 合并 的主流程
  report.py        # .bib / .report.json / .missing.txt 输出
  cli.py           # 命令行参数与退出码

gui/
  __main__.py      # python3 -m gui 入口（检查 tkinter）
  app.py           # 主窗口、列表、手动覆盖、Generate
  project.py       # .bibgui.json 工程模型、导入、检索、生成
```

## 关于 OpenAlex 的覆盖范围

OpenAlex 对 ACL Anthology、NeurIPS、ACM/IEEE 期刊等正式出版物的覆盖较好；但 ICLR、ICML 等大量论文在 OpenAlex 中可能只有 arXiv 记录，甚至没有 OpenReview 记录。此时程序会使用能找到的记录，并发出 `preprint_only` / `venue_mismatch` 警告，而不会伪造页码、出版社或正式 booktitle。需要 100% 正式版本时，请根据这些警告人工补全。
